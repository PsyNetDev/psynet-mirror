Fixed remote launches (`psynet deploy ssh`, `psynet deploy heroku`, `psynet debug ssh` and `psynet debug heroku`) silently wiping local data. They now say which local database and Redis they will clear, and ask first if that data looks in use: a local PsyNet server or another client is connected to the database, the database has participants, or Redis has keys. Pass the new `--yes` option to skip this question; it is required when the data looks in use and the session is non-interactive. `--update` launches no longer touch the local database, Redis or local servers. `psynet deploy heroku --docker` no longer runs a second, non-Docker deploy afterwards.
