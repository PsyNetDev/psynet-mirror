Fixed remote launches (`psynet deploy ssh`, `psynet deploy heroku`, `psynet debug ssh` and `psynet debug heroku`) silently wiping local data. They now say which local database and Redis they will clear, and ask first if that data is in use, that is, a local PsyNet server or another program is connected to the database or Redis. Pass the new `--yes` option to skip this question; it is required when the data is in use and the session is non-interactive. `--update` launches no longer touch the local database, Redis or local servers. `psynet deploy heroku --docker` no longer runs a second, non-Docker deploy afterwards.
