Remote deployments (`psynet deploy` and `psynet debug` to SSH servers or Heroku) now stop before anything else runs when a generated `constraints.txt` is out of date with `requirements.txt`. Previously, Docker deployments built the image from the stale lockfile and Heroku deployments without Docker regenerated it silently. Set `SKIP_DEPENDENCY_CHECK=1` to deploy anyway. A non-empty `constraints.txt` without the generator's header counts as written by hand, as in Dallinger: `psynet setup`, `psynet check-constraints` and the deployment check leave it unchanged.
