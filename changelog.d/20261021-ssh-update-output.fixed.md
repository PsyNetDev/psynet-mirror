Fixed the output of `psynet debug ssh` and `psynet deploy ssh`: after `--update`, the closing summary shows the participant link or recruiter's message saved when the app was deployed (or says that recruitment is unchanged), and the saved launch data keeps them; a confirmation answered through a pipe no longer runs onto the next line; and `psynet debug ssh --use-local-dallinger` no longer repeats Dallinger's message about the checkout it deploys. After an `--update`, `psynet export ssh` checks this directory against the commit the app now runs, instead of warning that it was launched from the first deploy's commit. `psynet export ssh` shows its download steps as one line each when its output is redirected, instead of spinner frames and a yaspin colour warning, and no longer reports materializing zero assets from the local cache.
