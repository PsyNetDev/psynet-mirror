`PushButtonControl`, `KeyboardPushButtonControl`, `RadioButtonControl`, `DropdownControl` and `CheckboxControl` now reject a submitted answer that is not one of their choices, so check two patterns that would otherwise leave participants stuck on "You need to select an answer!". First, if a control or page overrides `format_answer` to save something other than a choice, such as a dictionary of the choice and a reaction time, set `restrict_to_choices = False` on the control class or pass `restrict_to_choices=False` to the control; `TimedPushButtonControl` and its subclasses already do this. Second, the page is built again when the response arrives, so choices picked at random while building a page, for example with `random.sample` in a `PageMaker` or `show_trial`, must be the same each time: pick them once (in `finalize_definition` or `participant.var`) or pass `restrict_to_choices=False`. Each rejection logs a warning with the page label, the answer and the choices. The check catches out-of-range values from a tampered request and a bot `bot_response` of the wrong type (`"3"` for the choice `3`), and runs before any `validate`, so a control's or page's own `validate`, including a page that overrides `validate` like the demography `CountryOfBirth` page, cannot accept such an answer. Empty answers such as `None` still pass this check and are left to `force_selection`, and the free-text option of `RadioButtonControl` accepts any text. `CheckboxControl(force_selection=True)` now rejects a `None` answer instead of raising an error, and `DropdownControl(force_selection=True)` rejects it too.
