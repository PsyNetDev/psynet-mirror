Updated the Dallinger requirement to version 13.0.0 or above (see the [Dallinger 13.0.0 release notes](https://github.com/Dallinger/Dallinger/releases/tag/v13.0.0)). `POST /launch` now requires the dashboard login and refuses cross-site requests; `psynet debug local` and the deploy commands send the login for you, and `psynet debug local` launches its own experiment even when another experiment's worker on the same Redis database runs the launch job. `psynet deploy ssh` and `psynet debug ssh` leave naming an unpushed image to Dallinger, which names it after the app. Dallinger runs local servers with honcho rather than `heroku local`, adds real-time engine tables (`realtime_session`, `realtime_event`), which PsyNet now loads from database templates, and real-time runner processes, which PsyNet's local cleanup now stops along with web and worker processes, and ignores `lock_table_when_creating_participant`, which PsyNet no longer sets or documents. SSH launches with an app name that Dallinger reserves for the server, such as `logs` or `dallinger`, now stop before PsyNet prepares the experiment. Dallinger also adds `Experiment.check_recruiter_exit`, which lets an experiment refuse a `/recruiter-exit` request whose `unique_id` doesn't match the participant, moves to RQ 3 and Debian 13 Docker images, closes routes that trusted guessable participant ids, escapes JSON on the monitoring page, quotes worker ids in the dashboard's compensate commands, lets websocket clients stop reconnecting when the server refuses the connection, makes database resets check that Redis is reachable before dropping any tables, and makes `dallinger ec2` commands choose the right Route 53 hosted zone and wait for SSH after `ec2 start`.
