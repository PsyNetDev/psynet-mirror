A `SimpleGrouper` with `start_short_after` no longer shows a participant the other waiters' countdown when another request has just released them; until their page moves on, it shows the message for an unknown countdown (a callable `waiting_message` receives `seconds_left=None`). In sandbox and live deployments, barrier waiting messages and waiting-status updates now show an unknown countdown, with a warning in the log, if the release estimate fails; tests, `psynet debug local` and `psynet test local` still raise the error.
