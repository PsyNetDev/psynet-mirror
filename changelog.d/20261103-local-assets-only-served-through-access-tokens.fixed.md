`LocalStorage` no longer links `static/assets` to the asset storage folder, and removes such a link left by an earlier version when the experiment launches. The link let anyone who knew an asset's SHA-256 digest (for example of a published stimulus file) download it from `/static/assets/objects/sha256/<digest>` without its access token; assets are now served only through `/asset/<access_token>`. Locally stored assets are also served with the content type of their extension (for example `image/png` for a `.png` asset) rather than `application/octet-stream`. Every `/asset/<access_token>` response also sends `Content-Security-Policy: sandbox`, so an uploaded file cannot run as a page on the experiment's origin; PDFs, which Chrome's built-in viewer would not display when sandboxed, and redirects (for example to S3) are left unchanged. Assets still work as `img`, `audio` and `video` sources.
