`psynet performance-test ssh` now only runs on apps that it deployed for performance tests, never on an existing deployment, because the tests fill the app's database with bots and may reset it. If the server has no app named `--app`, it deploys the experiment from the current directory in debug mode, as `psynet debug ssh` does and with the same `--server`, `--dns-host`, `--ingress` and `--use-local-dallinger` options, so you no longer run `psynet debug ssh` first. The app's config sets the new `performance_test_app` variable and records a hash of the experiment's files and the PsyNet and Dallinger versions; later runs read both inside the app's web container, reuse the app, and update it first, keeping its database, when the hash has changed. An app without the mark, such as one deployed with `psynet debug ssh`, is refused with or without `--reset-database`, as is `psynet performance-test snapshots --app`; choose another app name. After a run the app is kept, and the command prints how to destroy it. Setting `performance_test_app = true` in `config.txt` yourself declares that the app's data is disposable, and `psynet deploy ssh` refuses to deploy with it set.
