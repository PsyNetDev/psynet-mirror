`psynet test local` and local `pytest` sessions (from the PsyNet checkout, or in experiments whose `pytest.ini` is up to date via `psynet scripts update`) now run in their own PostgreSQL database, Redis server, web port and development folder, so they no longer reset or stop a running `psynet debug local`, and several test sessions can run at once. If that environment can't be set up, the session stops with an error instead of touching the shared services, and it refuses to start while `psynet debug` serves the same experiment directory, whose generated files the tests would replace. `psynet performance-test local` and `psynet audit performance-test` (without `--existing`) get their own services and refuse in that case too. Each session's development folder is removed when it ends. Set `PSYNET_TEST_ENVIRONMENT=shared` to use the current services instead (the session then prints a warning, and other values are rejected); CI is unaffected. The experiment `pytest.ini` template now also collects the generated `test.py`, so plain `pytest` runs an experiment's tests.
