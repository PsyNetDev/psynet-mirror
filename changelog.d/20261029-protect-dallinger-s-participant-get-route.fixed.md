A request that has no dashboard login and knows only a participant's `participant_id` can no longer get the identifiers it needs to act as that participant through Dallinger's `GET /participant/<participant_id>` or `/recruiter-exit` routes, the Lucid `/terminate_participant` route, or `/response`. `GET /participant/<participant_id>` now returns nothing unless the request is logged in to the dashboard (nothing in Dallinger or PsyNet calls it), and `/recruiter-exit` needs the participant's `unique_id` as well as `participant_id`. PsyNet's Finish button, its redirect for finished participants and, on PsyNet pages, `dallinger.submitAssignment()` include it. Custom code that builds its own `/recruiter-exit` link with only `participant_id` now gets an error page and needs to add `unique_id`. `/terminate_participant` no longer finds a participant by `participant_id` alone; it takes `unique_id`, `RID` or `assignmentId`. `/response` now rejects an answer from a page other than the participant's current one even when a redirect is queued for them, for example after a sync-group partner leaves. Setting the `protected_routes` config variable no longer unprotects the routes PsyNet protects by default, such as `/network/<network_id>`: the configured routes are added to PsyNet's. To unprotect one of PsyNet's routes, override `Experiment.protected_routes` in your experiment class.
