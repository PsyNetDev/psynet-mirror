Added `psynet performance-test --n-bots auto`, which searches for the largest number of bots the server handles with no errors, a 95th-percentile response time under `--max-p95-ms` (default 500), and a 95th-percentile async-process queue wait under `--max-queue-p95-s` (default 5), counting processes still queued when the test ends. Each run's summary now reports this capacity, the 95th-percentile response time and queue wait per bot count and, once a larger count exceeded the limits, which limit it exceeded and a suggested `max_concurrent_participants` of 80% of the capacity. Tests whose bots didn't all start within the measurement window count as exceeding the limits, and async processes left queued by one test are given time to start before the next.
