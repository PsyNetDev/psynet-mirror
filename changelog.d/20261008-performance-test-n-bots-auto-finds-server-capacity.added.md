Added `psynet performance-test --n-bots auto`, which searches for the server's capacity: it doubles the bot count from 10 until a test has errors or exceeds the response-time or queue-wait limits, then bisects until the largest passing and smallest failing counts are within 10% of each other. It prints the most tests the search can take when it starts. A test in which new bots couldn't start fast enough also fails; this limits the test process rather than the server, so when it is the only limit the smallest failing count exceeded, the summary reports the capacity as a lower bound, explains that bots that take longer give a better measure, and doesn't suggest a participant cap. The audit's *Performance test* section suggests it when a run didn't use it.
