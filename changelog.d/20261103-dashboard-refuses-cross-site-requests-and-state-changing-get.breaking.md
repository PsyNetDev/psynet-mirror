The dashboard now refuses state-changing requests (POST, PUT, PATCH, DELETE) that a browser sends from another website, so a page on another site can no longer make a logged-in researcher's browser fail nodes, pay bonuses or archive deployments. This covers `/dashboard/...` routes and any other request made with the dashboard login. Scripts that call the dashboard with `requests` or the PsyNet CLI are unaffected. The dashboard routes that change state now accept only POST: `/dashboard/archive/deployment`, `/dashboard/restore/deployment`, `/dashboard/update/recruitment` and the Lucid status route, which has also moved from `/change_lucid_status` to `/dashboard/change_lucid_status`. Scripts that called these routes with GET must now POST the same parameters, for example `requests.post(f"{url}/dashboard/change_lucid_status", data={"status": "paused"}, auth=(dashboard_user, dashboard_password))`. Opening `/dashboard/export/trigger` (such as the Slack "Trigger export" link) now shows a button that starts the export instead of starting it straight away.
