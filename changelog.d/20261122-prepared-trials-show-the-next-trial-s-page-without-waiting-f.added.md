With `prepare_trials_in_advance=True`, trial pages built from simple built-in prompts and controls, such as an `ImagePrompt` with a `PushButtonControl`, now show the next trial as soon as the participant answers: each trial page carries the next trials' pages rendered in advance, the browser shows the next one as if the server had sent it, and the answers are sent to the server in the background. Other pages still wait for the server, including those whose answers it may turn down, such as with a `RadioButtonControl` or a `validate` function. A custom prompt or control can allow it by setting `can_swap_in_advance = True`, and the server log says why a trial maker's pages wait. So that pages rendered in advance can offer Leave too, the server now prepares the Leave offer when the participant clicks Leave, after the answers given ahead are saved, rather than each time it serves a page.
