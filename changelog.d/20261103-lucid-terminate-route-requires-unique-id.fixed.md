The Lucid `/terminate_participant` route now terminates an existing participant only when the request carries that participant's `unique_id`; a Lucid `RID` or `assignmentId` alone is refused with a 403 error. PsyNet sets a Lucid participant's worker ID to their RID, so their `unique_id` is `RID:RID`, and anyone who knows a respondent's RID can still terminate them; what protects the route is that Lucid generates the RID for each respondent. A bare `RID` still terminates a respondent who has no participant yet, as PsyNet's mobile-phone and browser checks on the ad and consent pages need. Because those checks send only the RID, a Lucid participant who has already started and opens the ad or consent page again now gets a 403 error page instead of being terminated and returned to Lucid. The route also refuses with a 403 error a request whose `assignmentId`, `RID` and `unique_id` name different respondents, refuses any request with a server error when several participants share the RID, returns a 404 error in experiments that don't recruit through Lucid, and returns a 400 error instead of a server error when the request names no respondent or its `unique_id` is not of the form `worker_id:RID`. PsyNet's own pages already send what the route needs; custom code that calls `/terminate_participant` for a participant with only `RID` or `assignmentId` must add `unique_id`.
