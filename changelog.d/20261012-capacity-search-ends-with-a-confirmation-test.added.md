Added a validation test to the end of `psynet performance-test --n-bots auto`: it runs the suggested participant cap with bots arriving over one session (or over `--arrival-minutes`), for two sessions, or a session longer than `--arrival-minutes` (at most an hour). The summary reports the cap as confirmed only if that test kept the limits and reached its steady state; otherwise it reports the cap as unconfirmed, with the limits the start-up and steady state exceeded and a lower cap to check if the test exceeded them, or a suggestion to rerun with `--reset-database` if it failed on data the search left behind. A validation test that could not measure the server, for example because the server stopped or no responses were recorded, leaves the cap unconfirmed without suggesting a lower one. Advice on queue waits, waiting participants, bot start rates, busy bot processes and PostgreSQL connections also covers failures of the validation test. Skip it with `--no-confirm`; it never runs with `--time-factor 0` or when the experiment's session length is unknown. The `--json-output` results now record each test's `arrival_minutes`, `session_minutes` and, for the validation test, `confirmation`, the number of async processes in each phase, and the options record `confirmation_skipped`.
