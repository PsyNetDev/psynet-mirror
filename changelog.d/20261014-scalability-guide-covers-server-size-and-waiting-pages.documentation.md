Rewrote the guide to testing scalability for the new `psynet performance-test`: running a test, controlling the load, reading the results, finding the server's capacity, sizing async workers, database size and resets over SSH, and every field of the `--json-output` file. It also documents that response times exclude time spent waiting for a free web worker, and how many participants can wait on waiting pages at once, which the bots don't measure. "Setting up a server" adds guidance on choosing a server size, with a measured example and a rule of thumb of 20 to 30 participants per vCPU. The implement-experiment agent skill suggests running the capacity search on an abridged version of a long experiment, then testing the full experiment at the recommended number of participants.
