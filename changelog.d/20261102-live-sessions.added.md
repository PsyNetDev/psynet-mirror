Added live sessions (`psynet.live_session`), games that a group of participants play together in real time on Dallinger's real-time engine. A game is a `LiveSession` subclass, and each kind of message its pages send is a `LiveMessage`, a Pydantic model that PsyNet checks before the game applies it. A `LiveSessionInitializer` starts a session for each group, with `settings` for the game if given, such as a trial's definition, and the game page, a `ModularPage` with a `LiveSessionControl`, plays it through `psynet.liveSession` in the page's JavaScript, which can show the player's own messages at once (`predict`) and other players moving smoothly between ticks (`interpolate`). A session starts once every player is ready or at the game's `ready_timeout`, and ends at its `max_duration` if the game hasn't ended it. The game page's answer is the session's outcome, and the page moves on by itself once the result is saved. The page shows a notice while another player is away from it, and when the participant's group has no session. A game pays bonuses with its `bonus` method and `queue_bonus`, bots play through its `bot` method, and `saved_messages`, `live_session_id` and `live_session_result` read a session's record. For a game with ticks, `psynet debug local` and `psynet deploy local` warn that their development server can deliver views late, and suggest `--legacy`. The live sessions guide explains how to write a game.
