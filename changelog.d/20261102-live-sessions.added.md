Added live sessions (`psynet.live_session`), games that a group of participants play together in real time on Dallinger's real-time engine. A game is a `LiveGame` subclass, and each kind of message its pages send is a `LiveMessage`, a Pydantic model that PsyNet checks before the game applies it. A `LiveGameBarrier` starts a session for each group, with `settings` for the game if given, such as a trial's definition, and the game page, a `ModularPage` with a `LiveSessionControl`, plays it through `psynet.liveSession` in the page's JavaScript, which can show the player's own messages at once (`predict`) and other players moving smoothly between ticks (`interpolate`). A session starts once every player is ready or at the game's `ready_timeout`, and ends at its `max_duration` if the game hasn't ended it. The game page's answer is the session's outcome, and the page moves on by itself once the result is saved. The page shows a notice while another player is away from it, and when the participant's group has no session. A game pays performance rewards with its `performance_reward` method, paid to every player once the session ends, and with `add_performance_reward` during the game. Bots play through its `bot` method, and `saved_messages`, `live_session_id` and `live_session_result` read a session's record. For a game with ticks, `psynet debug local` and `psynet deploy local` warn that their development server can deliver views late, and suggest `--legacy`. Live sessions build on PsyNet 14's multiplayer features. The game barrier is a `GroupBarrier` for the group's `group_type`, so it takes the barrier's options, such as `max_wait_time` and `max_wait_action`, and a participant who has left the group passes it and reaches the game page without a session. The game page's socket is admitted by the participant's `websocket_scope`. A game can be played as a cued trial with a `sync_group_type`, whose `show_trial` returns the game barrier and the game page: the game barrier is the group barrier that such a trial needs, and it closes the group's round when the game starts and records the session on it as `SyncGroupRound.live_session_id`. A game can give each player their own answer from the outcome (`answer`), record the group's results on its round (`record_round`), need a number of players (`min_players`) and time its rounds from the start (`elapsed`), and the game barrier's `on_release` runs once the session has started. The live sessions guide explains how to write a game.
