Added `psynet performance-test local --reset-database`, which starts every test from the same database: it copies the experiment's local database into a snapshot database before the first test and, before each later test, stops the server, recreates the experiment database from the snapshot and restarts the server, so that the tests of `--n-bots auto` compare load rather than amounts of data. The reset options need the isolated test environment's disposable database (they refuse `PSYNET_TEST_ENVIRONMENT=shared`) and a PostgreSQL role that may create databases. Before each copy, it checks that the disk has at least twice the database size free. `--prefill-participants N` first runs N bots through the experiment, 50 at a time and without pauses, so that every test starts with that much data; the pre-filled snapshot is kept and reused by later runs with the same experiment files (including `config.txt` and requirements), PsyNet and Dallinger versions and number of pre-fill participants. Kept snapshots are never changed; to pre-fill again, drop the snapshot with `psynet performance-test snapshots --drop NAME`. `--from-snapshot` starts from a kept snapshot even after the code has changed, and `psynet performance-test snapshots` lists and drops kept snapshots. A pre-fill in which any bot raises an error stops without keeping a snapshot. The JSON output records the reset and pre-fill options and the snapshot's name and row counts, and the capacity summary suggests `--reset-database` when tests started with different amounts of data.
