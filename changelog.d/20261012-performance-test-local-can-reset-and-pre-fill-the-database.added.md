Added `psynet performance-test local --reset-database`, which starts every test from the same database: it copies the experiment's local database into a snapshot database before the first test and, before each later test, stops the server, replaces the experiment database with a fresh copy of the snapshot and restarts the server, so that the tests of `--n-bots auto` compare load rather than amounts of data. The reset options only drop the database that the isolated test environment created for the run, so they refuse to run with `CI` or `PSYNET_TEST_ENVIRONMENT=shared` set, and they need a PostgreSQL role that may create databases. The copy is made before the experiment database is dropped, so an interrupted or failed reset never loses the data: PsyNet puts the experiment database back when the run ends or at the next reset. Before each copy, it checks that the disk has at least twice the database size free. `--prefill-participants N` first runs N bots through the experiment, 50 at a time and without pauses, so that every test starts with that much data; the pre-filled snapshot is kept and reused by later runs with the same experiment files (including `config.txt` and requirements), PsyNet and Dallinger versions and number of pre-fill participants. Kept snapshots are never changed; to pre-fill again, drop the snapshot with `psynet performance-test snapshots --drop NAME`. `--from-snapshot` starts from a kept snapshot even after the code has changed, and `psynet performance-test snapshots` lists kept snapshots and drops them, one at a time with `--drop NAME` or all of them on this computer with `--drop-all`. A pre-fill in which any bot raises an error stops without keeping a snapshot. The JSON output records the reset and pre-fill options and the snapshot's name and row counts, and the capacity summary suggests `--reset-database` when tests started with different amounts of data.
