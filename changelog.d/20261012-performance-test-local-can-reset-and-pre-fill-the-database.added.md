Added `psynet performance-test local --reset-database`, which starts every test from the same database: it takes a snapshot of the experiment's local database before the first test and restores it, with the server restarted, before each later test, so that the tests of `--n-bots auto` compare load rather than amounts of data. If the PostgreSQL role may not create databases, the snapshot is a `pg_dump` archive in the experiment's `.deploy/performance_snapshots` directory. `--prefill-participants N` (with `--prefill-bots` for how many run at once) first runs N bots through the experiment without pauses so that every test starts with that much data; the pre-filled snapshot is kept and reused by later runs with the same experiment files (including `config.txt` and requirements), PsyNet and Dallinger versions and pre-fill settings. `--fresh-prefill` pre-fills again, `--from-snapshot` starts from a kept snapshot even after the code has changed, and `psynet performance-test snapshots` lists and drops kept snapshots. A pre-fill in which any bot raises an error stops without keeping a snapshot. The JSON output records the reset and pre-fill options and the snapshot's name and row counts, and the capacity summary suggests `--reset-database` when tests started with different amounts of data.
