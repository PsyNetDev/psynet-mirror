Trial makers now choose each trial with one database query and load only the chosen node, instead of loading every eligible network and node, so selection no longer slows down as the number of nodes grows. Hooks such as `select_node` and `custom_node_filter` still receive the full list. Eligible candidates are now ordered by block, then by any custom priority, then by balancing, then randomly. When every candidate in the participant's remaining blocks is busy or full, `wait_for_networks=True` now makes the participant wait even if earlier blocks still have capacity.
