Added `prepare_trials_in_advance` to `StaticTrialMaker`: the trial maker creates a participant's trials in order when they reach it, and a trial page whose modules return `update` shows the next trial as soon as the participant answers. `update` also receives `upcoming`, the contents of the next known trials, for example to preload their stimuli. Answers given through `update`'s `response` handle are sent in the background, and if the server rejects one, PsyNet calls `update` again with that trial. This needs in-place timeline transitions, which are on by default. See the new `rapid_ratings` demo. Trial makers now also time out only their own trials.
