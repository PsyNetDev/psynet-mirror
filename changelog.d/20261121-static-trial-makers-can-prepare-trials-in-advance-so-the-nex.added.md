Added `prepare_trials_in_advance` to `StaticTrialMaker`: the trial maker keeps each participant's next few trials created, in order, ahead of the one they are on, and a `JSPage` trial page shows the next trial as soon as the participant answers. The `n_upcoming_trials` argument (2 by default) sets how many trials are prepared and sent to the browser ahead. It works with repeat trials and `recruit_mode="n_trials"`; with `check_performance_every_trial`, the next trials' files still download early but the trial after a checked trial waits for the check. The new `TrialMaker.should_check_performance_after` method chooses which trials are checked, for example only the last of each block, so the browser can run ahead over the others. `prepare_trials_in_advance` can't be combined with sync groups. `update` also receives `upcomingContents`, the contents of the next known trials, for example to preload their stimuli. Answers given through `update`'s `response` handle are sent in the background, and if the server rejects one, PsyNet calls `update` again with that trial. While answers are still waiting to be sent, the browser asks the participant before the page closes. It only runs ahead with in-place timeline transitions, which are on by default. A trial whose page has different HTML, JavaScript or `page_config` from the current one waits for the server instead, and PsyNet logs a warning naming the trials: what changes between trials belongs in the page's `contents`. Bot tests such as `psynet test local` fail if a trial maker compared its trial pages but couldn't show any in advance. The next trials' pages are built before the earlier trials are answered, so if `show_trial` depends on an earlier answer, the browser replaces the page shown in advance with the server's once the server replies and logs a warning, which also reaches the server log; the `playwright-testing` skill shows how to make an experiment's Playwright tests fail on it. Trial pages also list the files of the next trials' pages, such as `AudioPrompt` sounds and `ImagePrompt` pictures, and the browser downloads them while the participant works on the current trial; custom pages can list more through `Page.prefetch_urls`. Page modules can load sounds with the new `psynet.media.loadAudio(url)`, and the response handle's `startClock(at)` and `answer(value, {at})` accept `performance.now()` timestamps, such as a key press's `event.timeStamp`, so `time_taken` can measure reaction times. `response.mark(name)` records when each step of a trial answered in several steps happened. See the new `rapid_ratings` demo; the `simple_audio_rating` demo now prepares its trials in advance. Trial makers now only time out their own trials and trials without a trial maker, rather than every trial of their trial class.
