Added `prepare_trials_in_advance` to `StaticTrialMaker`: the trial maker creates a participant's trials in order when they reach it, and a trial page whose modules return `update` shows the next trial as soon as the participant answers. `update` also receives `upcomingContents`, the contents of the next known trials, for example to preload their stimuli. Answers given through `update`'s `response` handle are sent in the background, and if the server rejects one, PsyNet calls `update` again with that trial. While answers are still waiting to be sent, the browser asks the participant before the page closes. This needs in-place timeline transitions, which are on by default. A trial whose page has different HTML, JavaScript or `js_vars` from the current one waits for the server instead, and PsyNet logs a warning: what changes between trials belongs in the page's `contents`. Trial pages also list the files of the next trials' pages, such as `AudioPrompt` sounds and `ImagePrompt` pictures, and the browser downloads them while the participant works on the current trial; custom pages can list more through `Page.prefetch_urls`. Page modules can load sounds with the new `psynet.media.loadAudio(url)`, and the response handle's `startClock(at)` and `answer(value, {at})` accept `performance.now()` timestamps, such as a key press's `event.timeStamp`, so `time_taken` can measure reaction times. `response.mark(name)` records when each step of a trial answered in several steps happened. See the new `rapid_ratings` demo; the `simple_audio_rating` demo now prepares its trials in advance. Trial makers now only time out their own trials and trials without a trial maker, rather than every trial of their trial class.
