`NumberControl` now saves the answer as a number, for participants and default bots alike: an `int` for a whole number such as `100` and a `float` otherwise, so typing `78.5` saves `78.5` instead of the string `"78.5"`. Code that converts the answer with `float(...)` or `int(...)` still works, but code that compares it to a string, such as `answer == "100"`, must compare to a number instead. `NaN` and infinity are now rejected. A fixed bot answer is saved as given, so it must be a number too: `bot_response=25` passes validation, `bot_response="25"` fails it.
