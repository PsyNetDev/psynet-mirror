Barrier checks skip released hold waiters after the check commits, one participant at a time, so last-arrival does not first-paint the next stacked wait. The visit claim is a transaction lock on a second connection until that skip finishes, so a concurrent GET still waits for the same key after partner row locks drop. Last-arrival parks hold-wake publish from the moment it starts following a visit, and Redis park/unpin is atomic, so the poller cannot wake waiters while that GET is still rendering.
