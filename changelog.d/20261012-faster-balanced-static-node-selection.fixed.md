Fixed balanced node selection (the ``StaticTrialMaker`` default, ``node_order="balanced"``) slowing down as an experiment collects trials: each candidate node's trial count is now read from a new partial index on the trial table instead of from every trial row, so choosing a trial at 200,000 trials takes about 15 ms instead of 300–800 ms. The same applies to chain trial makers with ``chain_order="balanced"`` and to node capacity checks.
