Updated the SSH deployment docs and the deployment skills for Dallinger's `dallinger docker-ssh servers upgrade`: deployments only add their own Caddy route, `servers add` and `dallinger ec2 provision` set up the shared Caddy, Postgres and Dozzle services and leave their files read-only, and the log viewer has its own password at `https://logs.<server>`. A new section explains how to upgrade an existing server once and why everyone who deploys to it must update Dallinger. The docs also say that server commands read a real `contact_email_on_error` only from `~/.dallingerconfig`, and what `dallinger ec2 provision` checks before booting an instance. The troubleshooting page covers the new setup, contact-email and `PermissionError` messages.
