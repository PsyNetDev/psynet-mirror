`PushButtonControl`, `KeyboardPushButtonControl`, `RadioButtonControl`, `DropdownControl` and `CheckboxControl` now reject a submitted answer that isn't one of their choices, before it is formatted or validated, so a tampered request can't reach `format_answer`, `validate` or code that expects a valid choice. The participant sees "That option is no longer available. Please reload the page." and PsyNet logs a warning, because choices built from live state (such as the creations of a sync group's members) can also change between drawing the page and submitting it. PsyNet builds the page again when the answer arrives, so choices drawn at random in a page maker or `show_trial` must be stored, for example in the trial's definition, and not drawn again. Custom JavaScript or subclasses that submit values outside `choices` are rejected too; use a plain `Control` for such pages. Empty selections, radio free text, `TimedPushButtonControl` (whose answer is the event log) and bots that submit a formatted `answer` are still accepted.
