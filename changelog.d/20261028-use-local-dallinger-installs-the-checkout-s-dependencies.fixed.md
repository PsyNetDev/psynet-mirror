Fixed `--use-local-dallinger` (in `psynet debug ssh` and `psynet performance-test ssh`) building an image that lacked dependencies added in the local Dallinger checkout, so the app could build and then answer 503. The image now installs the checkout's missing dependencies, keeping the pinned versions that satisfy it, and the build fails if a local PsyNet or Dallinger build conflicts with the other installed packages. If the experiment `Dockerfile` still installs the local Dallinger without its dependencies, `--use-local-dallinger` stops and says so: run `psynet scripts update` to refresh a generated `Dockerfile`, or change that line in a customised one. A PsyNet or Dallinger version mismatch before deploying now shows a short error instead of a Python traceback, and the `SKIP_VERSION_CHECK` message names both packages.
