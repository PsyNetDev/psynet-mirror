Added `--reset-database` and `--prefill-participants N` to `psynet performance-test ssh`, so that every test starts from the same data and the tests of `--n-bots auto` compare load rather than amounts of data. Before the first test PsyNet copies the app's database into a temporary snapshot in the app's PostgreSQL container; before each later test it stops the app's containers except PostgreSQL, Redis and the front door, recreates the database from the snapshot, empties the async job queues and starts the stopped containers again. `--prefill-participants N` implies `--reset-database` and first runs N bots through the experiment, 50 at a time and without pauses. When the run ends, also after a failed reset or an interrupt, PsyNet restores the database to how the run found it, before any pre-fill, and drops its copies; if it can't restore it, it keeps the copy, explains how to recover by destroying the app and running the test again, and fails. A failed reset stops the run but still prints the summary and writes the JSON for the completed tests, with the error as `reset_error`. A worker that hangs at start-up after a reset is left to Dallinger's `worker_startup_timeout`, which exits it so that Docker starts it again; PsyNet waits up to 180 s for the workers to register, printing progress, and otherwise fails with an error that names the workers that didn't register and gives the `docker compose restart` command. Resets never touch an experiment in live mode, even with `--force`, and are refused when the disk lacks twice the database's size free. These options are only available over SSH.
