Dictionaries stored in the database, such as `participant.var`, `trial.var`, `node.var` and trial answers and definitions, now keep the type of their keys. Before, integer keys silently came back as strings, so `participant.var.choice_by_player = {12: "rock"}` read back as `{"12": "rock"}`. Now it reads back as `{12: "rock"}`, and `choices[participant.id]` works. Code that worked around this by reading such keys as strings, for example `choices[str(participant.id)]`, must use the original keys instead; converting with `int(key)` still works. A dictionary with both string and non-string keys keeps its key types but not its key order: string keys come first. Such a dictionary makes Flask's `jsonify` and Jinja's `tojson` raise `TypeError`, because they sort keys, and tuple keys make any `json.dumps` raise; convert the keys before sending the value to the browser, for example with `{str(k): v for k, v in d.items()}`. In the database and its exports, a non-string key is written in jsonpickle's tagged form, for example `{"json://12": "rock"}`, as tuples and other non-JSON values already were; `psynet.export.unpack_json_column` removes the tag, so this becomes a column named `12`. Dictionaries stored with string keys, including any stored before this change, are unchanged.
