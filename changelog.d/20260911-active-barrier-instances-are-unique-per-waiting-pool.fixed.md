Active barrier instances are unique per waiting pool. A concurrent insert collision reuses the committed winner instead of splitting the group. If a visit was marked inactive while waiters remain, the next arrival reactivates that visit instead of opening a second pool, and the poller still evaluates a grouped visit with unreleased working participants. Checking a leftover visit moves its unreleased waiters onto the live pool instead of stealing that pool's unique index. Empty ungrouped visits deactivate so a later grouper with the same ID can open a new pool.
