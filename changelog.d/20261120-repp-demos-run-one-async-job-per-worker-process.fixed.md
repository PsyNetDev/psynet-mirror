Fixed intermittent HTTP 503 responses in the REPP tapping demos (`tapping_iterated`, `tapping_memory`, `tapping_static`, `repp_prescreen` and the `tapping` pipeline). A tapping analysis never yields to the other async jobs running in its worker process, so a job holding the participant's database lock could stall until the participant's next response timed out. These demos now set `config = {"worker_greenlets_per_process": 1}` on `Exp`; experiments with CPU-heavy async jobs should do the same and scale with more worker processes instead.
