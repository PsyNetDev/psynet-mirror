Added CPU workers for CPU-heavy async jobs, such as recording analyses. Each worker process now starts `cpu_processes_per_worker` CPU workers beside it (default 1), which run CPU-heavy jobs one at a time, so that they no longer stall the other async jobs of a worker process. Recording trials such as `AudioRecordTrial` mark their analysis as CPU-heavy; mark your own trial's analysis with `async_post_trial_cpu_heavy = True` on the trial class, or any worker job with `WorkerAsyncJob(..., cpu_heavy=True)`. This fixes intermittent HTTP 503 responses in the REPP tapping demos, where a job holding the participant's database lock stalled behind an analysis until the participant's next response timed out. The performance test counts the CPU workers and sizes `worker_processes` for them too. Needs Dallinger with `cpu_processes_per_worker`.
