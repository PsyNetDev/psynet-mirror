Added CPU workers for CPU-heavy async jobs, such as recording analyses. Each worker process now starts `cpu_processes_per_worker` CPU workers beside it (default 1), which run CPU-heavy jobs one at a time, so that they no longer stall the other async jobs of a worker process. This fixes intermittent HTTP 503 responses in the REPP tapping demos, where a job holding the participant's database lock stalled behind an analysis until the participant's next response timed out. `psynet test local` warns when a job's measured CPU time contradicts its `cpu_heavy` declaration, and the performance test counts the CPU workers and sizes `worker_processes` for them too.
