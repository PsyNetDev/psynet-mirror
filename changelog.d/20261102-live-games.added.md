Added live games (`psynet.live_game`), games that a group of participants play together in real time on Dallinger's real-time engine. A game is a `LiveGame` subclass, and each kind of message its pages send is a `LiveMessage`, a Pydantic model that PsyNet checks before the message's `apply` changes the state. The players are numbered from 0, in the order of their seats in the group, and pages see only these numbers, never participant ids. The game's methods get each player's number and `now`, the seconds since the game started. A `PlayLiveGame` in the timeline, given the `group_type` that plays and the `game_class`, waits for each group's members, starts a game for the group, with `settings` for it if given, such as a trial's definition, and shows them its game page, a `ModularPage` with a `LiveGameControl`, which plays the game through `psynet.liveGame` in the page's JavaScript. The page can show the player's own messages at once (`predict`) and other players moving smoothly between ticks (`interpolate`), and has the player's number (`player`) and the game's clock (`gameTime()`). A game starts once every player is ready or at its `ready_timeout`, and lasts its `duration`, which pages count down with `secondsLeft()`, or, for a game that ends by itself, ends at its `timeout` if it hasn't ended by then. Pages enable their controls only while the game is played with `enableWhilePlaying`, and check `playing`. The game page's answer is the game's outcome, or each player's part of it (`answer`), and the page moves on by itself once the result is saved, or after showing it for the control's `show_result_for` seconds. The page shows a notice while another player is away from it, and when the participant's group has no game. A game pays performance rewards with its `performance_reward` method, paid to every player once the game ends, and with `add_performance_reward` during the game; in a trial, both are also added to the trial's `performance_reward`. A message type's `should_save` can leave its messages out of the game's record. Bots play through the game's `bot` method, `LocalGame` in `psynet.live_game.testing` plays a game in Python for tests, and `saved_messages`, `live_game_id` and `live_game_result` read a game's record. A game can need a number of players (`min_players`, `max_players`), and a `PlayLiveGame`'s `on_release` runs once the group's game has been created. For a game with ticks, `psynet debug local` and `psynet deploy local` warn that their development server can deliver views late, and suggest `--legacy`. Live games build on PsyNet 14's multiplayer features. The wait at a `PlayLiveGame` is a `GroupBarrier` for the group's `group_type`, so `PlayLiveGame` takes the barrier's options, such as `max_wait_time` and `max_wait_action`, and a participant who has left the group passes the barrier and reaches the game page without a game. The game page's socket is admitted by the participant's `websocket_scope`. A game can be played as a cued trial with a `sync_group_type`, whose `show_trial` returns a `PlayLiveGame`: its barrier is the group barrier that such a trial needs, and it closes the group's round when the wait ends and records the game on it as `SyncGroupRound.live_game_id`, and its outcome, once saved, as `SyncGroupRound.live_game_outcome`. The live games guide explains how to write a game.
