Added live games (`psynet.live_game`), games that a group of participants play together in real time on Dallinger's real-time engine. A game is a `LiveGame` subclass with a `name`, and each kind of message its pages send is a `LiveMessage`, a Pydantic model that PsyNet checks before the message's `apply` changes the state, or turns the message down with `Reject`, which `psynet.live_game` exports. The players are numbered from 0 in the order they joined the game, those who start it together in seat order, and pages see only these numbers, never participant ids. The game's methods get each player's number and `now`, the seconds since the game started. A `PlayLiveGame` in the timeline, given the `group_type` that plays and the `game_class`, waits for each group's members, starts a game for the group, with `settings` for it if given, such as a trial's definition, and shows them its game page, a `ModularPage` with a `LiveGameControl`, which plays the game through `psynet.liveGame` in the page's JavaScript. The page updates itself in `onChange`, whenever the game as the player sees it changes, can show the player's own messages there at once (`predict`) and other players moving smoothly between ticks (`interpolate`), reads each view as it arrives with `onReceive`, and has the player's number (`player`), how to show each player (`players`, by pseudonym, or as the same figure with the control's `names="anonymous"`) and the game's clock (`gameTime()`). A game starts once every player is ready or at its `ready_timeout`, and one that no player has opened by then ends with the reason `"not_joined"`. It lasts its `duration`, which pages count down with `onTimeLeft`, or, for a game that ends by itself, ends at its `timeout` if it hasn't ended by then. Pages enable their controls only while the game is played with `enableWhilePlaying`, check `playing`, and show why the game rejected the player's latest message with `showRejections`. The game page's answer is the game's outcome, or each player's part of it (`answer`), and the page moves on by itself once the result is saved, or after showing it for the control's `show_result_for` seconds. The page shows a notice while another player is away from it, and when the participant's group has no game. A game with an `away_timeout` ends with the reason `"players_left"` once fewer than `min_players` players have stayed away for less than that long. A game pays performance rewards with its `performance_reward` method, paid to each player once their game ends, and with `add_performance_reward` during the game; in a trial, both are also added to the trial's `performance_reward`. A message type's `should_save` can leave its messages out of the game's record. A game that fails, because its code raised an error or its record couldn't be saved, fails its players as any other error in the experiment does: their game page raises `LiveGameFailed`, with the game's own error, which PsyNet records for the dashboard before the participant leaves through the error page. Bots play through the game's `bot` method, `LocalGame` in `psynet.live_game.testing` plays a game in Python for tests, including players leaving and rejoining. A `LiveGameRecord` reads a game's record back: its `status`, including `"not_started"` for a step where the group started no game, whether it `finished`, its `outcome` and `end_reason`, the participant's `answer` and `player` number, every player's `answers`, and its `messages`, `moments` and `checkpoints`. On later pages, `participant.live_games` and `live_game_history`, keyed by the `PlayLiveGame`'s id, give each participant's games as records, `Trial.live_game` the game played in a trial, and `SyncGroup.running_live_games` the games a group is playing now. A game can need a number of players (`min_players`, `max_players`), and a `PlayLiveGame`'s `on_release` runs once the group's game has been created, with its record as `live_game`. A game can keep going while players come and go: with `join_running_game=True`, a member who reaches a `PlayLiveGame` while their group's game from it is running joins that game, which makes room for them in its `on_add`, and a game's `is_done` can end one player's game while the others play on, with their answer and reward from the outcome then. A game records what happened along the way with `record`, which a record's `moments` reads back, and its `checkpoints` are the copies of its state that Dallinger saved. For a game with ticks, `psynet debug local` and `psynet deploy local` warn that their development server can deliver views late, and suggest `--legacy`. Live games build on PsyNet 14's multiplayer features. The wait at a `PlayLiveGame` is a `GroupBarrier` for the group's `group_type`, so `PlayLiveGame` takes the barrier's options, and needs a limit on its wait: `late_after`, which allows for the time limits of the pages before it, or `max_wait_time`, and a participant who has left the group passes the barrier and reaches the game page without a game. The game page's socket is admitted by the participant's `websocket_scope`. A game can be played as a cued trial with a `sync_group_type`, whose `show_trial` returns a `PlayLiveGame`: its barrier is the group barrier that such a trial needs, and it closes the group's round when the wait ends and records the game on it as `SyncGroupRound.live_game_id`, and its outcome, once saved, as `SyncGroupRound.live_game_outcome`. The live game tutorial walks through three demo games, and the live games reference covers the rest. A game's outcome defaults to its final state, a player away for its `away_timeout`, 60 seconds by default, counts as gone, and pages show the game's status with `showStatus`. On a page without a game, `psynet.liveGame` does nothing and PsyNet hides the elements marked `data-live-game`. The experiment refuses two `PlayLiveGame` steps with one id, live games whose bots `psynet test` would run one at a time, and a game played in a trial that pays through both the game and the trial.
