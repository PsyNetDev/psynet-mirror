Added a way to present a trial maker's trials on a single live-game page, with one trial still saved per response. `LiveTrialGame` presents a `StaticTrialMaker`'s trials, created up front, and can send upcoming stimuli to the browser so the next one appears immediately. `OnDemandTrialGame` asks the trial maker for the next trial after each answer, for adaptive tasks such as staircases. Pages answer with a `TrialAnswer` message and time responses in the browser with `game.startResponseClock(view)`. `PlayLiveGame` no longer needs `group_type` for one-player games. Trial makers gain `present_trials()`, `get_public_definition(trial)` and `check_performance()`, and `response_timeout_sec=None` turns off the response timeout. See the new "Keeping a task on one page" guide and the `live_trial_game`, `live_trial_game_images` and `live_trial_game_adaptive` demos.
