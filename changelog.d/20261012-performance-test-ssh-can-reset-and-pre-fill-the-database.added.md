`psynet performance-test ssh` now takes `--reset-database`, `--prefill-participants` and `--from-snapshot`, like `psynet performance-test local`. With them, your computer runs the series of tests or the capacity search, one test at a time on the server. Before each later test, PsyNet stops the app's web, worker, clock and PgBouncer containers, replaces the app's database with a copy of a snapshot inside the app's PostgreSQL container, and starts the containers again; after a failed or interrupted reset it puts the database back and starts the containers it stopped, or prints the command that starts them. The real-data guards run before every reset, and neither command resets an experiment in live mode, even with `--force`. Snapshots are named after the app, `psynet performance-test snapshots --app NAME` lists and drops one app's snapshots, and `psynet destroy ssh` drops the app's pre-fill snapshots. A pre-fill now warns when the database already has participants. `--json-output` now also works with `psynet performance-test ssh`.
