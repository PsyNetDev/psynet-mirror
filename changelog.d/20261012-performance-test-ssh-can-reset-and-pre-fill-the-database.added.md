Added `--reset-database` and `--prefill-participants N` to `psynet performance-test ssh`. `--reset-database` starts every test from the same database, so that the tests of `--n-bots auto` compare load rather than amounts of data: before the first test PsyNet copies the app's database into a temporary snapshot in the app's PostgreSQL container, and before each later test it stops the app's running or restarting containers except PostgreSQL, Redis and the front door (so also any services you added that use the database), recreates the database from the snapshot, empties the async job queues and starts again only the containers it stopped. When the run ends, also after a failed reset or an interrupt, PsyNet restores the database to how the run found it, before any pre-fill, so that every run starts from the same data, and drops its copies; if the restore fails, it keeps the copy and prints how to restore the database by hand. After a failed or interrupted reset PsyNet starts the containers it stopped, or fails and prints the command that starts them. Before every reset, the app's web container checks that the app is one that `performance-test ssh` deployed for its tests and runs the real-data guards; a reset never touches an experiment in live mode, even with `--force`, and refuses when the disk lacks twice the database's size free or the free space can't be checked. It warns when the snapshot already holds participants. `--prefill-participants N` implies `--reset-database` and first runs N bots through the experiment, 50 at a time and without pauses, so that every test starts with that much data; a pre-fill in which any bot raises an error stops the run. With or without these options, your computer now runs the series of tests or the capacity search, one test at a time on the server, with the same test lengths, `--arrival-minutes` and validation test as a local run, and `--json-output` now also works with `psynet performance-test ssh`, recording the reset options and the snapshot's row counts. When tests started with different amounts of data, the capacity summary suggests `--reset-database` after a `performance-test ssh` run, and restarting `psynet debug local` for a fresh database after a local one.
