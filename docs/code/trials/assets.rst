===============
Managing assets
===============

An :class:`~psynet.asset.Asset` is a file or folder that PsyNet keeps track
of during an experiment: a stimulus attached to a module or node, a file
generated by code, or a participant recording. PsyNet uploads assets to
storage, serves them to participants, records them in the database, and
exports the ones created during the experiment.

Assets are stored on the web server that runs the experiment by default. To
store them in Amazon S3 instead, set ``asset_storage`` on the experiment class
to an :class:`~psynet.asset.S3Storage`:

.. code-block:: python

    import psynet.experiment
    from psynet.asset import S3Storage

    class Exp(psynet.experiment.Experiment):
        asset_storage = S3Storage("my-bucket", "my-experiment")

.. warning::
    Deploying thousands of assets can be slow. For large sets of ready-made
    files, see :ref:`large_stimulus_sets`.

Creating an asset
-----------------

:func:`~psynet.asset.asset` creates an asset from its source:

.. code-block:: python

    from psynet.asset import asset

    asset("logo.svg")                         # a file or folder
    asset("https://example.com/logo.svg")     # a URL, not uploaded
    asset(make_logo, extension=".svg")        # a function that writes the file
    asset(make_logo, extension=".svg", on_demand=True)  # regenerated on each request

Paths are relative to the experiment directory, or absolute.

.. note::
    If you keep asset source files in your experiment directory, put them in
    ``data/``, which the stock ``deploy.toml`` leaves out of the deployment
    package. Otherwise they are uploaded twice: once in the package and once
    as assets.

PsyNet uploads an asset only once it is linked to the experiment: through a
module or node in the timeline, as described below, or by depositing it with
a parent while the experiment runs.

Accessing assets
----------------

Participants, modules, nodes and trials each have an ``assets`` dictionary:

.. code-block:: python

    participant.assets
    module.assets
    node.assets
    trial.assets

The key describes the asset's role for that object, for example
``trial.assets["stimulus"]``. The same asset can have different keys on
different objects: a recording can be the response for one trial and the
stimulus for another.

Exporting assets
----------------

``psynet export`` includes assets created while the experiment was running,
such as recordings, but not assets prepared before launch; see
:ref:`export_assets`.

Notes for advanced users
------------------------

Types of assets
^^^^^^^^^^^^^^^

:func:`~psynet.asset.asset` returns one of these classes:

- :class:`~psynet.asset.FileAsset`, made from an existing file or folder,
  such as a stimulus file, a recording or an analysis plot.
- :class:`~psynet.asset.GeneratedAsset`, made by running a function that
  writes the file, so stimulus generation code can live in the experiment.
- :class:`~psynet.asset.OnDemandAsset`, like a generated asset but never
  stored: the file is generated each time it is requested. Use it for files
  that are quick to generate.
- :class:`~psynet.asset.ExternalAsset`, a file hosted elsewhere and
  referenced by URL. :class:`~psynet.asset.ExternalS3Asset` is an external
  asset in an S3 bucket.

Whether an asset is exported follows from when it was deposited, not from
where it is declared. File and generated assets deposited while the
experiment is running are exported, including assets of a module built
inside a page maker. Assets prepared before launch are not: files come from
the experiment directory, and generated assets are recreated at every launch.
On-demand and external assets are never exported.

"Before launch" means while PsyNet prepares the deployment, which covers the
timeline's assets and the start nodes of across-participant chains. Assets
deposited later count as created during the experiment and are exported, even
if they come from the experiment directory: for example, assets deposited in
an ``on_launch`` hook, or the start nodes of within-participant chains, which
are created for each participant.

Storage and URLs
^^^^^^^^^^^^^^^^

Managed assets are stored by SHA-256 content hash under
``objects/sha256/<digest>``, so bytes that are already stored are not
uploaded again. With local storage, and for on-demand assets, the browser
fetches assets from ``/asset/<access_token>``, where the token is random
rather than derived from the content. If a local asset is deposited again
with different contents, its token changes and the old URL stops working.
S3-backed assets use a direct public S3 URL, which changes when the
contents change. External assets keep their original URL.

.. note::
    Earlier PsyNet versions called file assets ``ExperimentAsset`` or ``CachedAsset``, called
    generated assets ``CachedFunctionAsset``, and accepted ``asset(..., cache=True)``. The old
    names still work but are deprecated, and ``cache`` has no effect.
