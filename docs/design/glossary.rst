Glossary
========

.. glossary::
   :sorted:

   Archive
      A saved copy of an experiment's database. Redeploying from an
      archive continues data collection with an existing experiment; see
      :doc:`/deploy/reference/deploy_from_archive`.

   Asset
      A file that PsyNet stores and tracks, such as a recording made by a
      participant or a stimulus generated by code. Ready-made stimuli usually
      live in ``static/`` instead; see :doc:`/design/stimuli`.

   Auto-recruit
      A recruitment mode that invites a new participant each time one
      finishes, keeping the number of active participants roughly
      constant at :term:`initial_recruitment_size`. You can toggle it from
      the experiment dashboard; switch it off before ending a study.

   Barrier
      A point in the timeline where the members of a group wait until all of
      them have arrived; see :doc:`/design/groups`.

   Basic data
      A summary of an experiment's data that the experimenter defines for
      analysis; see :doc:`/data/basic_data`.

   Block
      A set of trials that a participant takes together. A trial maker can
      present its blocks in a fixed or random order; see :doc:`/design/trials`.

   Bot
      A simulated participant that takes the experiment automatically, used
      for testing; see :doc:`/test/backend`.

   Chain
      A sequence of nodes in which each node is created from responses to
      the previous one, as in serial reproduction or Gibbs Sampling with
      People; see :doc:`/design/chains`.

   Code block
      A timeline element that runs code without showing the participant a
      page; see :doc:`/design/timeline`.

   Control
      The part of a page through which the participant responds, such as
      buttons, a slider or an audio recorder; see :doc:`/design/pages`.

   Dashboard
      The experimenter's web interface to a running experiment, for
      monitoring participants, viewing data and exporting; see
      :doc:`/deploy/reference/deployment_monitor`.

   Docker
      Container software that PsyNet uses to run PostgreSQL and Redis on
      your computer and to build the image that a server runs when you
      deploy; see :doc:`/deploy/how_deployment_works`.

   Experiment hosting
      The server that runs your experiment during data collection: either
      a server you manage yourself or an EC2 server provisioned on AWS.
      See :doc:`/deploy/how_deployment_works`.

   Export
      A copy of an experiment's data, downloaded for analysis; see
      :doc:`/data/what_an_export_contains`.

   Generic recruiter
      A recruiter that recruits nobody and prints a participant link
      instead. Use it for pilot runs you share with colleagues before
      recruiting real participants.

   Grouper
      A timeline element that forms groups of participants as they arrive;
      see :doc:`/design/groups`.

   initial_recruitment_size
      The experiment setting that controls how many participants are
      invited when recruitment starts. Avoid inviting more participants
      than your server can handle.

   Launch
      Deploying an experiment with ``psynet deploy ssh`` so that the
      configured recruiter starts inviting participants.

   Locale
      The language an experiment is shown in. Each deployment runs in one
      locale; see :doc:`/code/participants/internationalization`.

   Module
      A named, self-contained part of a timeline, such as a questionnaire or
      a trial maker; see :doc:`/design/timeline`.

   Node
      The thing a trial is about, for example a stimulus to rate. Trial makers
      assign participants to nodes; see :doc:`/design/trials`.

   Page
      One screen of the experiment; see :doc:`/design/pages`.

   Page maker
      A timeline element that builds a page when the participant reaches it,
      so the page can depend on earlier responses; see :doc:`/design/timeline`.

   Participant group
      A label that reserves particular nodes for particular participants, for
      example to assign conditions; see :doc:`/design/trials`.

   Performance check
      A check that scores a participant's trials, for example at the end of a
      trial maker, and can fail participants who score too low; see
      :doc:`/design/trials`.

   Prompt
      The part of a page that the participant sees or hears, such as text,
      an image or a sound; see :doc:`/design/pages`.

   Provisioning
      Setting up a server to host experiments, typically an EC2 server;
      see :doc:`/deploy/reference/aws_automatic_provisioning`.

   Recruiter
      The service that invites and pays participants, optionally
      filtering them by demographic requirements. Examples include
      Prolific, CINT (formerly Lucid), and Lab Recruiter.

   Remote debug
      Running ``psynet debug ssh`` to test an experiment on its server
      before launch. It uses the configured recruiter, so pilot with the
      :term:`generic recruiter` to avoid inviting real participants.

   Response
      What a participant submitted on a page, stored with the page's label;
      see :doc:`/design/pages`.

   Teardown
      Shutting down a server once data collection is finished, typically
      terminating an EC2 instance so it stops incurring costs.

   Time estimate
      How long a part of the timeline is expected to take. PsyNet pays
      participants by time estimates and uses them for the progress bar; see
      :doc:`/design/participants`.

   Timeline
      The sequence of pages, code blocks and trial makers that a participant
      goes through; see :doc:`/design/timeline`.

   Trial
      One presentation of a node to a participant, together with the
      response; see :doc:`/design/trials`.

   Trial maker
      A timeline element that decides which trials each participant takes;
      see :doc:`/design/trials`.
